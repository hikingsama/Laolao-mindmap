# Laolao-mindmap · 捞捞思维导图（独立版）

从 [hangyuan2024-hue/class-calendar](https://github.com/hangyuan2024-hue/class-calendar) 根目录的
`mindmap.js` 独立出来的仓库，单独演化，**不回灌主站**。

第一版做的事：**把"位置"提升为数据**。坐标存在导图层 `cur.pos`，
拖到哪、位置就是数据；旧导图首次打开会播种一次坐标；新建节点出生就固化位置。

---

## 怎么跑（写死，不用改参数）

```bash
node server.js
```

然后打开：

```
http://127.0.0.1:8788
```

端口**固定 8788**，不随机、不跟随参数。零依赖，不需要 `npm install`。
（`npm start` 等价于 `node server.js`。）

## 自带自测

先在一个终端跑 `node server.js`，再在另一个终端跑：

```bash
node tools/smoke.js
```

它会启一个浏览器环境仿真台，把 `vendor/mindmap.js` 真跑起来，逐条验证验收情况。

### 可选：UI 级验收（需要真实浏览器）

自测台没有真实布局/命中测试，以下几条要真浏览器才算数。装着 Edge（或 Chrome）时可以一条命令跑完：

```bash
node tools/verify-ui.mjs                 # 默认 http://127.0.0.1:8788/
node tools/verify-ui.mjs --port 9000     # 换端口（或 --url http://… --edge <exe> 指定浏览器）
```

它是**开发工具**，不参与运行时：不被打包、不影响 `node server.js`，也不写仓库（临时浏览器 profile 建在系统临时目录、结束即删）。
验的是：页面能开、双击空白建点中心落在鼠标点、收起按钮第 1 次点就生效、删整棵子树后导图层无孤儿、撤销"新建"后无孤儿。
需要 Node ≥ 22（用到内置 WebSocket），且服务已在跑。

## 数据契约（第 10 条：定下即 API 契约）

```js
cur.pos  = { "<节点id>": { x: 378, y: -120 } }   // x/y    = 节点左上角，舞台坐标系
cur.size = { "<节点id>": { w: 180, h: 56  } }    // w/h    = 节点宽高，单位与 pos 同一坐标系
```

- **两样都绝不写进节点字段**：安卓端 `MindMapDocument.normalizeNode()` 是白名单式过滤，节点字段会被静默丢掉（硬规则第 2 条）。
- `pos` 没有条目的节点仍按旧布局算法排，只是会被挪开避免压在一起。
- `size` 的不变量：
  1. 没有条目的节点，用它**当次文本测量结果**固化一次，之后不再重算（F5 重开不重算已固化值）；
  2. **下限 60×40**；**上限 = 该节点文本测量尺寸的 4 倍**（`clampSize()` 换算）。读取时也会过一遍 clamp，防手改/导入的 JSON 里出现 1×1 或 99999×99999。

## 鼠标交互

| 操作 | 效果 |
|---|---|
| 拖节点 | 自由定位（写 `cur.pos`）；落到别的主题上/下沿仍会改变父子关系 |
| 拖空白 | 平移画布（滚轮横向/纵向滚动，Ctrl+滚轮缩放） |
| 点节点 | 选中；**选中后右下角出现缩放柄** |
| 拖缩放柄 | 改 `cur.size`，松手才落盘（整段拖拽只进一条撤销历史）；**按住 Shift 锁比例** |
| 双击空白 | 新建子节点，先算一次尺寸与坐标、立刻固化，不压父节点 |

## 第一版不做

自动布局开关 /「一键整理重排」、云同步（`mm_save` / `CCAuth` 全部打桩或剥离）、回灌主站、构建工具链重构。

## 已知限制

1. 本机直连 `github.com` 不通（TCP 超时），推送需要走本机代理并在**仓库本地** git 配置里设 `http.sslBackend=openssl`；token 需要 `Contents: Read and write`。这些都是**这台机器的环境**，不是项目要求，所以没有写进仓库。
2. 拖动一个**带子节点**的父节点时，子节点会跟着位移（保住相对位置），但不会重新布线。
3. 旧导图的播种只做一次，之后位置就是数据，不会自动重排。
4. 仓库里有**两份**导图代码：`vendor/mindmap.js`（页面实际加载的那份，含坐标改动 + 云同步已停用）和根目录 `mindmap.js`（早期"停用云同步"的基线副本，页面不加载）。合并成一份还没做 —— 这是已知的重复，不是设计。
5. **尺寸上下限**：下限 `60×40`，上限 = 文本测量尺寸的 4 倍。上限是"防误拖到离谱"的护栏，不是设计上的美学标准，后续可调。
6. **缩放柄的鼠标交互只能在真实浏览器里验**：本地自测台（`tools/smoke.js`）没有真实布局引擎，验证的是**数据层**（`cur.size` 生成、clamp 边界、落盘、二次打开不重算），按下/拖动/松手这条链路它测不了，已显式标注"未覆盖"。
7. **改尺寸可能推动"没被拖过"的节点重排**：尺寸在 `measure()` 之后、写进布局表之前就合并（这样 `span()` 的子树跨度缓存才按最终尺寸算），因此**没有固化坐标的节点**会按新尺寸重新参与打包而移动。**播种完成后所有节点都有固化坐标，所以正常情况下看不到这个影响**；只有新建/导入进来、还没落过坐标的节点会受影响。这条是设计的必然结果，不是 bug。
