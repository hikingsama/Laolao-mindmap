# 捞捞思维导图

面向课程学习的思维导图工作台：把笔记、公式、图片与讲义组织成可编辑的知识节点，通过连续提问逐步理解，并保留回到原始资料的入口。

当前为 **v0.1 · 单用户本地版**，使用浏览器界面与本机 Node.js 服务。本文按 2026-10-26 的代码编写，默认使用本仓库的 `main` 分支。

## 快速开始

### 下载与安装

需要 **Node.js 22.13 或以上版本**，建议使用桌面版 Edge 或 Chrome。

```bash
git clone https://github.com/hikingsama/Laolao-mindmap.git
cd Laolao-mindmap
npm ci --omit=dev --ignore-scripts
```

也可下载 main 分支的 ZIP，解压后在项目目录执行安装命令。首次运行需要安装依赖；更新锁文件后应重新安装。

项目采用原生 HTML、CSS、JavaScript，没有前端编译步骤。浏览器依赖随 `vendor/` 分发，本机 PDF 与图片处理使用锁文件中的 `pdfjs-dist@6.4.299` 和 `@napi-rs/canvas@1.0.10`。

### 启动

```bash
npm start
```

打开 **[http://127.0.0.1:8796/](http://127.0.0.1:8796/)**。也可运行 `node server.js`。

Windows 用户可双击 **启动服务.cmd**，启动后输入 `1` 打开网页，输入 `2` 停止服务并退出。服务窗口需要保持运行，后台生成期间电脑也需保持唤醒、联网。停止服务前先保存导图。

更新代码后重新安装有变化的依赖、重启服务，并在浏览器按 **Ctrl+Shift+R** 强制刷新。多份项目副本各自保存数据，请确认启动的是准备使用的目录。

### 首次配置

- 首页“你的学习背景”或顶部“学习背景”：填写年级、专业和已学课程。全部可选，整个模块共用，不要求每张导图重复填写。
- 顶部“大模型 API 接入”：选择服务商或自定义兼容接口，填写模型名称、接口地址和 API Key，测试后保存。当前提供 DeepSeek、GLM、Kimi 和自定义接口配置入口。
- 图片识别、图片提问及 PDF 视觉读取需要所选模型支持图像输入。手工创建、编辑和管理导图不需要模型配置。

AI 调用使用你配置的模型平台，相关内容会发送到该平台，费用与限额由平台决定。本机配置文件含密钥，备份或分享项目时请排除该文件。

### 连续提问

选中节点后发起提问。每轮默认生成 **1–3 个知识节点**，总正文以 **100–250 字**为目标，沿讲解顺序形成短链；必要公式、条件和完整论证可适度超出，不重新改写之前的节点。

关联与定向、回答两个角色共享本轮可追溯的原图、PDF 页和完整相关正文。超过应用容量会明确提示，不用截短摘要静默替代原件；已经遗失的原件也不会凭空恢复。下一步追问方向使用独立 Markdown 副标题展示。

每对节点只保留一条可见连接。长节点可按题目、概念或推导阶段分节；需要时进行数学排版与节点内分节复核。分节复核仅允许补充标题，不改写正文和公式，也不承担知识正确性审查。

### 从资料生成导图

| 输入入口 | 处理流程 |
| --- | --- |
| 粘贴大纲／正文／笔记 | 保留完整输入 → 全文主题与步骤规划 → 按完整语义单元生成 |
| AI 识别图片 | 保存原图 → 识别完整正文 → 全文规划 → 回读相关原图并生成 |
| 按主题编写学习稿 | 根据主题、目标和学习背景拟稿 → 标记为 AI 编写 → 规划并生成 |
| 课件／讲义 PDF | 通览全部材料 → 建立全文索引与全局计划 → 回读完整单元对应原文与页图 → 生成 |

文字入口统一通过 AI 理解生成，已移除“无模型本地解析”的生成选项。可勾选“先查看、修改识别正文与全文规划”，核对后再继续；修改正文会重新规划，并保存原始输入和修订记录。

PDF 支持多文件、按讲义分支或跨讲义主题融合，以及自动图文、逐页视觉、仅文字读取方式。主题融合把跨页、跨文件的完整知识单元组织起来。分批传输服务于通览和完整单元回读，不把固定页段直接当作独立知识点。

生成过程参考全局学习背景，并包含数学排版检查、按需节点内分节复核及整图结构复核。模型仍可能漏读或理解错误，可通过出处和生成记录对照原件；这些复核不等于独立事实审查。

当前主要输入范围：

- 文字／识别正文：最多 **200000 字符**；主题与目标输入：最多 **3000 字符**。
- 图片识别：最多 **8 张** PNG、JPEG 或 WebP，单张最多 **20 MiB**，合计最多 **80 MiB**。
- PDF：最多 **32 份**，单份最多 **50 MiB**，合计最多 **512 MiB**；PPT/PPTX 请先导出 PDF。

这些是应用上限，实际范围还取决于模型的上下文与视觉能力。超过范围会提示调整材料，不自动裁掉尾部。详见 [文字与图片生成](docs/text-background-tasks.md)、[本地后台讲义生成](docs/local-background-tasks.md)。

## 后台任务

| 操作 | 是否接入持久后台队列 |
| --- | --- |
| PDF／讲义生成 | 是 |
| 正文、图片识别、主题拟稿生成 | 是 |
| 普通节点提问 | 否，仍使用当前页面的提问流程 |
| 跨导图总结 | 否，仍使用原有生成流程 |

收到“已提交本地后台任务”后，可以切换或关闭整个浏览器。任务由本机 Node.js 子进程处理，原件、进度、阶段输出和结果独立保存；上传尚未完成时应保持页面打开。

从顶部“后台任务”查看进度、待核对正文与规划、停止、继续或领取结果。结果追加到目标导图，保留期间的手工编辑，也可以作为新导图打开，整次加入支持一步撤销。

当前队列串行运行。服务停止或电脑关机后不会继续计算；重启服务后可手动继续未完成阶段，已完成阶段复用。若某次模型请求是否完成无法确认，重新调用前会提示可能再次计费。

任务资料保留至主动清理。清理后，已加入导图的正文和已复制的媒体仍保留；依赖任务原件的后续回读可能受影响，重要资料可选择嵌入导图。

## 文件夹、多选与回收站

首页和侧边栏共用选择状态。勾选文件夹会递归包含所有子内容，取消其中一个子项后祖先显示为部分选中；跨目录与搜索保留选择，批量操作自动去重。

- “全选可见内容／导图”选中当前显示项目，全选后变为“取消全选”。
- 移动、删除等管理操作不受 8 张限制；**多图总结**仍只接受 **2–8 张已保存导图**，不能混选文件夹。
- 删除文件夹会把文件夹及全部子内容一起移入回收站，操作前显示实际数量并确认。
- 回收站支持搜索、批量恢复、彻底删除和清空。恢复保留目录层级、导图、草稿及附件，彻底删除不可恢复。

详见 [导图库与回收站](docs/library-management.md)、[双画布](docs/map-workspace.md)、[引用与多图总结](docs/map-references-and-summary.md)。

## 数据保存与备份

| 数据 | 默认位置或规则 |
| --- | --- |
| 正式导图、附件与恢复草稿 | `storage/maps/` |
| 文件夹归类、回收站 | 导图存储目录内的 `.library.json`、`.trash/` |
| 模型配置 | `.local/ai-config.json`，含本机 API 密钥 |
| 全局学习背景 | `.local/student-profile.json` |
| 后台原件、检查点与独立结果 | 未设置 MM_STORAGE_DIR 时为 `.local/lecture-tasks/`；设置后默认位于导图目录的父目录下 `lecture-tasks/` |

**启动服务.cmd** 默认把 `MM_STORAGE_DIR` 设置为本项目的 `storage/maps`，因此通过该脚本启动时，后台任务默认位于 **storage/lecture-tasks/**。

可通过环境变量 `MM_PORT`、`MM_STORAGE_DIR`、`MM_AI_CONFIG_FILE`、`MM_STUDENT_PROFILE_FILE`、`MM_LECTURE_TASK_DIR` 分别覆盖端口和对应数据位置。

迁移或备份时先保存并停止服务，再复制实际使用的导图目录和任务目录；学习背景与模型配置按需单独备份。浏览器中的未保存编辑也可能保存在本机恢复草稿中，迁移前应先正式保存。

本仓库沿用已有示例导图与附件；本轮发布没有新增上传本机个人导图、任务资料或密钥。`.gitignore` 排除新产生的存储、配置、任务和依赖目录，但不取消历史上已跟踪的文件，分享前请检查提交内容。

## 项目结构

```text
index.html              浏览器入口
server.js               本机 HTTP 服务
js/                     编辑器、导图库、AI 接口及后台任务模块
css/                    界面样式
prompts/                生成、规划与复核角色的提示词
vendor/                 编辑器核心及浏览器依赖
tools/                  启动器、验证脚本与维护工具
docs/                   使用、实现与交接文档
package.json            Node.js 版本要求与运行依赖
package-lock.json       固定依赖版本
```

编辑器实际核心位于 `vendor/mindmap.js`，相关模块位于 `js/`；历史根目录的 `mindmap.js` 不是当前唯一实现入口。

## 开发验证

项目没有统一的 npm test。按改动范围运行对应脚本，例如：

```bash
node tools/verify-text-task-plan.cjs
node tools/verify-text-tasks.cjs
node tools/verify-local-lecture.cjs
node tools/verify-question-sources.cjs
node tools/verify-section-review.cjs
node tools/verify-folder-trash.cjs
```

上述验证使用临时资料与本地模拟模型，不需要真实 API 密钥；它们检查程序流程、材料传递及恢复行为，不衡量真实模型识别准确率。带 -ui 的浏览器验证另需 Playwright 与对应浏览器，依赖不包含在应用的运行依赖中。
