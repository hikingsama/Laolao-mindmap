# 提示词维护与生成调查

顶栏“提示词与过程”，或生成窗口“查看提示词”，提供只读入口。进度面板“查看生成过程”可看本次调用，处理中可点“刷新过程”。

## 模板位置

| 文件 | 用途 |
| --- | --- |
| prompts/outline.md | 粘贴大纲、正文或笔记的结构整理 |
| prompts/lecture-survey.md | 通览全部材料，建立内容索引和跨页承接线索 |
| prompts/lecture-plan.md | 阅读完整索引，安排主题、完整内容单元与前后依赖 |
| prompts/lecture-extract.md | 回读完整内容单元的原文及页图，提炼节点与出处 |
| prompts/lecture-merge.md | 仅保留旧版章节汇总调用兼容 |
| prompts/content-sections.md | 正文生成共用的节点内分节、分步和题目排版规则 |
| prompts/planner.md | 节点提问的关联资料选择、回答定向 |
| prompts/node-graph.md | 节点提问直接生成导图 |
| prompts/node-summary.md | 问答内容节点整理兼容模式 |
| prompts/node-chat.md | 文字回答兼容模式 |
| prompts/math-review.md | 数学定界符、上下标与LaTeX排版复核 |
| prompts/structure-review.md | 全讲模块合并、主次层级及原节点归属复核 |

js/ai-prompts.cjs注册及渲染模板；js/ai-outline-prompt.cjs保留旧调用接口。结构验证、传输协议、取消与保存限制由程序执行。

## 人工调查步骤

1. “提示词模板”查看当前文件内容与哈希版本。
2. “当前导图的生成记录”查看相应任务的已完成、未完成页码与错误。
3. 展开模型阶段，查看实际系统提示词、模型、输入、输出。节点提问还可查看关联与定向的输入、输出。
4. 对照模板版本和实际版本：{{supplementRule}}会按是否允许补充替换，正文生成会附加content-sections.md与已填写的学习背景，所以实际版本可能不同。模板查看入口同时显示共用规则，历史阶段保留当时实际系统提示词。
5. 确认问题发生于文字提取、来源范围还是融合，再调整对应文件。模板每次新请求重新读取，历史保留当时的实际版本。

图像输入使用说明占位，不保存图片编码、密钥或思考正文。文字输入与输出会随导图保存、JSON导出，应按自己的学习资料管理。旧记录可能没有快照，界面会说明。

## 修改约定

直接编辑UTF-8 Markdown模板，下一次调用生效，不必新建API配置。保持输出JSON字段、来源格式与占位符约定；改提示词不能绕过程序校验。

当前没有用户自定义编辑器。后续可以在注册表之上加入用户覆盖、恢复默认、修改预览和版本管理，结构校验继续由程序执行。

验证：node tools/verify-ai-files.cjs、node tools/verify-lecture-semantics.cjs；浏览器：node tools/verify-lecture-semantics-ui.cjs（需要Playwright及Edge，或通过--edge/--chrome指定浏览器）。旧浏览器测试入口verify-ai-files-ui.mjs默认转到新版语义流程；--legacy-v1仅用于旧版协议的历史样例。浏览器测试使用自动分配的独立端口、临时目录、假模型与临时浏览器资料，不调用真实账号。

## 知识单元与连线格式（2026-10-22）

五份结构化生成模板统一以完整知识单元为节点：同一概念的定义、记法、条件、性质和简短例子可放在一起；连续推导在节点内部用说明与独立公式逐行展开，只有新主题、独立引理或自然子论证才分节点。节点数量是上限，不是生成目标。

新连线格式：`{"from":"n1","to":"n2","kind":"relation","label":"是其特例"}`。

- kind优先使用hierarchy（层级）、inference（推导）、relation（一般关联，缺省值）。旧八种kind继续兼容，旧图及历史无需迁移。
- label自由使用简短的学科关系文字，如“等价于”“反例”“适用条件”，建议2–12字，程序上限40字符、单行纯文本。显而易见的层级可写空字符串，画布不显示标签。
- 提供label时优先展示label，未提供时使用该kind的默认文字。新hierarchy默认空标签。parallel兼容无箭头并列，其他关系默认from指向to；措辞应与此方向一致。
- 端点、重复、环、连通性与出处仍严格校验，不能通过自定义文字绕过。

改变模板只影响之后生成的内容，不自动合并、重排或改写已保存节点。新版PDF在生成知识正文前，先收齐所有文件的内容索引，统一规划完整语义单元，再回读相应原文；不再用最初的传输窗口决定知识边界。当前单元直接依赖的前文携带完整正文，来源与范围均受校验，所有阶段保留详细记录。

新增验证：`node tools/verify-ai-relations.cjs`，覆盖标签、流式解析、默认值、旧关系兼容及整批撤销/重做。

## 数学排版review（2026-10-22）

结构化文字、PDF及节点问答生成后，先做本地检查：上下标、LaTeX命令、裸露希腊字母、数学语境的变量、定界符与KaTeX语法。代码、链接、路径、文件名及已有公式受保护。明确标注的行内等式、求和和分数不再被自动升为独立公式；主要推导继续通过math块独立分行。

仅有疑点时额外调用一次当前模型，按本次生成批次复核；不是逐节点调用，没有新增配置。复核只能建议给原文中的确切表达式添加公式定界符，程序验证原文匹配、保护范围、语法与句内/独立位置，不接受修改字母、数值、上下标或推导。复核字段上限48000字符、最多128条建议，最长等待45秒，不自动重试付费请求。大批资料的每个生成批次独立检查。

存疑节点及其后续节点等复核结束再进入画布，前面已通过检查的节点仍可流式出现，避免随后覆盖用户编辑。停止会取消复核。失败、超时、无法唯一定位或需猜补内容时保留原文，以“公式待检查”标记；用户修正后重绘会移除标记，历史audit保留。

在生成记录的具体阶段查看“数学排版review：状态、修改与待检查项”：含本地疑点、实际review模板/输入、修改前后、拒绝原因和剩余问题。有疑点时另存review前原始节点。图像编码、密钥和思考正文不进入记录。已有导图不会自动送审或改写。

相关代码：ai-math-check.js（本地检查和受限修改）、ai-math-review.cjs（单次模型复核）、prompts/math-review.md。验证：node tools/verify-ai-math-review.cjs。

已有文字节点：右键 → “检查数学排版”，先查看修改前后，再“应用修改”；支持一步撤销，保留节点身份、坐标、连线和出处。如果预览后节点又被编辑、删除或切换导图，拒绝应用旧结果。复核过程单独存为当前导图的生成记录。图片/PDF文件节点不提供此正文检查入口。

## 主题归属与层级（2026-10-22）

outline、lecture-extract、lecture-merge、node-graph、node-summary新增可选字段：

- topic：稳定的课程主题名，同一主题复用同名，不用页码、文件名、批次或每个节点的标题来充当主题。总览可省略。一个节点只归属一个主主题，跨主题关系用边表达。
- parentId：仅明确的整体与部分层级，指向本次输出中另一个节点；允许省略。推导、等价、反例等不应当变成包含层级。引用须存在且不成环。
- lecture-extract输入的topicHints是前序批次已使用的名称提示，用于名称一致，不是新增事实依据；融合摘要同样保留topic。

程序映射真实节点ID，按实测尺寸与主题归属安排团块和层级底色；模型不负责坐标或颜色。生成中仍依次显示节点，完成时对本轮节点做一次整理；按钮整理完全在本机执行，不增加模型调用。旧图没有这些元信息时按既有分支排布，不自动补送资料。改变模板只影响之后调用，不会重新解析已保存内容。

## 同次生成的简明概述（2026-10-22）

outline、lecture-extract、lecture-merge、node-graph、node-summary要求每个知识节点同时给出brief，建议40–100字、程序最多280字符。用1–2句文字说明核心内容、作用与层级联系；避免LaTeX、长公式和完整计算过程。主题中心的概述应覆盖其分支范围，不能引入原资料之外的知识。

brief与详细blocks来自同次结构化响应，不独立调用模型、不增加配置或模板数量。生成解析、流式完整节点、数学复核及最终画布均保留brief；PDF后续融合输入同样携带它。概览按主题组织brief，点击卡片进入真实节点；旧图没有brief时列出已有主题/标题，不自动补发模型请求。可以在“提示词与过程”核对实际返回的brief与生成模板。

生成模板同时减少批次占位中心，要求第一个节点表达实际章节或课程主题；分批主题中心也应填写实际topic，后续批次复用合适topicHints。颜色仍由程序的柔和色板分配，模型仅判断语义归属与层级。

## 整图结构review（2026-10-22）

AI文字与PDF生成全轮结束、融合完成后，另发一次结构复核（超过100节点时分层）。复核范围是本轮知识节点，既有导图通过“结构复核”主动发起时是整图知识节点。输入包含原节点ID、标题、brief、topic、parentId；缺少brief时正文摘录最多320字符；目录线索最多12段，每段1400字符。不会重新发送PDF页面或图片。分层包作为不可拆分单元，最后恢复原ID覆盖。

输出root / modules / children归属树及合并理由；所有原ID恰好归属一次。程序拒绝未知、重复、遗漏ID、越界深度和无效代表节点。通过后保留节点正文、公式、出处和推导/应用/关联边；调整topic、layoutParent并重建内部包含边。概览和详细布局共用此归属，颜色与坐标仍由本地程序决定。

audit保存在生成记录structureReview字段，包含各阶段实际模板版本、输入、验证后输出和失败原因；“提示词与过程”统一呈现。正常一次付费请求；大于100节点按100节点分块、最多4层/24次保护，不自动重试。180秒总复核超时，取消中止实际网络请求。失败不应用方案；手动预览后内容或结构变化时拒绝应用过期方案。已有导图仅打开不会自动调用。

代码：structure-plan.js（输入/归属校验、投影与应用）、ai-structure-review.cjs（同配置模型调用及分层）、ai-structure-review-ui.js（流程与手动预览）；验证：tools/verify-structure-review.cjs、tools/verify-structure-review-ui.mjs。

## 归并与学习顺序（2026-10-22）

structure-review.md加强“先归并再排序”：检查同义/重复、同一板块碎分、尺度混杂与单节点模块；对照目录，不机械强制模块数。输入在父级之外增加本轮节点间的实际知识连线（from/to/kind/label），不包含外部节点。分层复核将连线映射到当前包，过滤包内与未提供引用。

输出modules数组就是最终学习顺序，children及nodeIds也尽量按自然阅读顺序排列；orderReason说明排序依据。模型不在title里添加数字。程序依据数组连续分配order，持久化到结构方案；概览、详细布局、代表标题和分组标签共用该顺序，先左列再右列。阅读顺序不会额外生成声称知识推导的边。旧方案没有order时不会假装完成了新的顺序审查，可主动重新复核。

讲义学习清单完全在本地维护，不新增模型请求或提示词。module-learning.js定义五步标签、说明与状态归属；记录按原节点成员集合匹配，重命名/排序保留，归并/拆分不自动继承完成状态。moduleLearning与节点提问aiMemory分别保存。
