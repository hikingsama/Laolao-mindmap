# 本地课程与思维导图交接

此次改动只作用于这两个本地项目，不涉及远程仓库。

## 使用

1. 按原启动方式运行课程后端，浏览器打开 `http://127.0.0.1:3012/`。不要直接双击前端 HTML。
2. 在配套思维导图目录运行 `node server.js`，默认地址是 `http://127.0.0.1:8796/`。
3. 在课程的资料/笔记详情点击“在导图中编辑”。有导图时恢复导图；首次使用时按大纲生成。
4. 修改后点击编辑器操作栏的“保存并回传课程”。收到成功提示后，切回课程页面会刷新当前资料预览。
5. “上传导图备份 / 图片”保留为手工回传入口。导图 JSON 会同时重建大纲缓存；图片通过 Data URL 读取。

## 数据与行为

- 大纲和导图 JSON 通过接口传输，网址仅携带短的交接参数。交接凭据放在网址片段中，不进入常规 HTTP 请求路径。
- 每份课程资料绑定稳定的导图编号；刷新和再次编辑不会反复新建同一份导图。
- 交接记录落在课程的 `back/data/mindmap-handoffs.json`，服务重启后仍可使用。链接有效期七天，过期后从课程页重新进入。
- 回传前先完成本地正式保存；课程端确认保存后显示成功。网络失败不会删除本地导图。
- 回传带版本校验。其他窗口已更新课程时，旧窗口回传会提示冲突，不覆盖新版本。从课程重新进入发现不同版本时另开版本，原本地内容保留。
- 传输格式为 v3 扁平 nodes + edges。旧的 children 树（包括错误标记为 v3 的树）会补齐连线。
- 两端统一缩进、Markdown 标题和中文编号解析；保留数学负号；空大纲不创建导图。单份交换数据最多 4MB、1500 个节点、64 层。
- 此入口导入课程已经生成的大纲，不额外调用思维导图中的 AI 生成流程。
- 本次回传同步导图 JSON、布局和结构预览。图片/PDF 二进制文件仍由导图本地媒体目录管理，不会随 JSON 自动上传到课程服务器或其他设备。

## 配置与源码

默认配置匹配本机课程页面 3012、业务接口 3000、导图端 8796。正式部署改地址时，需要同时配置：

- 课程前端：在 `outlineMap.js` 加载前设置 `globalThis.MINDMAP_APP_URL`；接口地址沿用 `globalThis.COURSES_API_BASE`。
- 课程后端：环境变量 `COURSES_HANDOFF_ALLOWED_ORIGINS`，逗号分隔准确的课程页面和导图页面 origin（协议、主机、端口）。
- 思维导图：在 `courses-handoff.js` 加载前设置 `window.COURSES_HANDOFF_ALLOWED_ORIGINS` 为允许的课程后端 origin 数组。

来源校验针对交接接口生效，不替代整个课程系统未来的用户认证。

格式模块有三份无构建分发副本：课程 `fronted/js/mindmap-interchange.js`、课程 `back/mindmap-interchange.cjs`、导图 `js/mindmap-interchange.js`。维护时保持内容一致；新增测试会检查课程前后端副本。

`handoff/` 下是供交接时复制的编辑器脚本副本。已经修补的导图项目无需重复复制。若部署到其他导图副本，须同时复制两个 JS，并在 HTML 中依次加载格式脚本、交接脚本，不能仅替换一个文件。

## 验证

安装课程后端原有依赖后，从课程项目根目录运行：

```text
node tests/mindmap-handoff.cjs
```

测试只创建临时数据，不读取用户数据库；覆盖分层、连线、循环图预览、长大纲、来源校验、稳定编号、版本冲突、重复回传、服务重启和链接过期。

本轮另以临时数据库和真实浏览器完成了 16 项联调检查：打开、编辑、保存回传、预览、刷新去重、再次编辑以及并发冲突全部通过。

原有全量回归在数据库迁移断言处停止：测试期待 schema 20，下载版本的实际 schema 已为 24。相关 schema 和迁移测试均非本次修改；本轮未调整它们。
