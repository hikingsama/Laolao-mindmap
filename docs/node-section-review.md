# 节点内分节复核

本阶段检查节点内部的副标题与步骤排版，不检查知识、数学、OCR或原文完整性，不重新读取原PDF或图像。知识理解仍由关联员与回答员共享完整材料；分节复核是生成后的受限排版步骤。

## 范围与时间

节点提问（node-graph）、讲义/PDF语义单元提炼（lecture-extract）及文字／图片后台单元生成（text-extract）在数学排版检查之后执行本阶段。调查索引、全文规划、整图结构复核不经过此步骤。新的粘贴正文、图片与主题拟稿后台流程均已接入；多图总结和手工编辑未新增此复核。

程序先判断：简短正文（可见文字不超过100字符、总长不超过240字符）不强制加标题；已有至少两个正文三级标题且各段长度合理时，通过格式检查。其余节点交给模型判断。代码块中的“###”不算副标题，“下一步可以问”也不能替代正文分节。

每轮提问最多一批（1～3个节点），讲义按最多8个节点、约16000字符分批；一个超过该软阈值但仍合法的完整节点单独送入，不裁正文。每批一次模型请求，同时检查并给标题补丁，不再另发重写请求。仅使用本批完整正文，不发送原件图像。输出预算至多4096 tokens、每批等待上限45秒，无自动重试；实际用量与耗时记录在生成过程。此前3～10秒/提问的估计不是实测承诺，取决于模型和节点长度，已规范节点不会新增模型调用。

## 允许的修正

程序提供安全边界编号及完整正文片段。模型只可指定在某边界之前插入“### 标题”，不能返回新的正文。数学、代码、链接等内部不可作为插入位置；长正文的边界过多时合并片段，全文保持不变。模型必须确认覆盖本批每个节点，不需要修改的节点只确认、不加标题。

补丁校验拒绝未知/重复节点、虚构边界、重写字段、注入公式/代码的标题和孤立空泛分节。保留正文原字节、公式、选项、节点编号、简述、主题、连线和出处。它可以补充标题，不能把一段需要完全改写的混乱正文伪装成排版已修复；模型判断仍可能有误，不代表语义正确性保证。

## 显示、失败与保存

提问仍流式显示完整节点。复核结束后，仅向尚未被用户修改或删除的本轮节点补充分节；保持位置，自动尺寸未被用户调整时可增加高度。更新并入原生成批次，仍可整轮撤销/重做，不覆盖等待期间的编辑。

讲义在后台保存修正后的单元。复核失败或超时保留原文，在提问完成状态或后台任务状态提示“分节待检查”。停止按钮会中止复核；不假装完成，不自动重复付费请求。生成过程包含sectionReview的程序判断、批次输入、标题补丁、拒绝原因、状态与用量，查看“提示词与过程”即可追溯。

更新后需重启本地服务并强制刷新页面。旧进程不支持本阶段时，新的提问/讲义提交会提示重启；不改写已经保存的旧节点。已有未完成后台任务按原检查点恢复规则处理。

验证入口：`node tools/verify-section-review.cjs`；`node tools/verify-section-review-ui.cjs`（需Playwright、Edge及PDF依赖）。测试使用本地假模型和隔离资料，覆盖安全补丁、正文/公式保留、批处理、失败/超时/停止、实际流式更新、用户编辑、撤销与后台PDF结果。
