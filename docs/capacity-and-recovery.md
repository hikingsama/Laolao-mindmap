# 容量与恢复缓存

“设备存储空间已满”的旧提示来自浏览器 localStorage 写入失败，并不等同于硬盘容量不足，也不等同于单图文件限制。

导图正文、生成记录与恢复快照改用 IndexedDB；本地服务仍把正式版本和草稿分别保存在项目的 storage/maps 中。localStorage 只保留索引、界面偏好等小数据。旧正文和恢复副本在完整写入 IndexedDB 后才移除旧副本；浏览器缓存失败时保留内存内容，并单独报告缓存问题。浏览器未提供 IndexedDB 时兼容旧缓存方式，本地文件保存仍然独立工作。

| 项目 | 当前应用上限 |
|---|---|
| 单图JSON（节点、关系、生成记录等） | 512 MiB；讲义生成超过480 MiB时暂停新调用 |
| 单次大纲／正文／提问文本 | 200000字符 |
| 一次请求全部对话文本 | 600000字符 |
| 发往本地AI接口的请求体 | 256 MiB |
| 生成回答正文接收量 | 32 MiB，按UTF-8字节计算 |
| 流式传输量（含包装和思考片段） | 256 MiB |
| 单条流式消息 | 64 MiB |
| 主要生成环节的输出预算 | 默认32768 tokens；可在现有“大模型API接入”中按服务商设置1024–131072 |

图片和PDF作为独立附件保存，不计入单图JSON上限；单个图片20 MiB、PDF50 MiB的附件上限保持原值。关联规划等辅助环节在配置预算之内使用更小的角色预算。长内容仍分批处理，单次主生成等待上限延长至10分钟。

应用上限不代表所选模型支持的上下文或输出窗口。输出预算应填写平台支持的值；平台若拒绝，不会自动重试付费请求。token并非字数，部分平台会把思考token计入完成用量。

“提示词与过程 → 当前导图的生成记录 → 某次模型阶段 → 容量、用量与结束原因”显示请求预算、接收字节数、平台结束原因和平台提供的用量。平台没有提供或旧记录没有保存的数字明确显示未记录，不用配置上限代替实际用量。此次更新不重新调用旧任务，也不改写旧生成记录。

生成时默认展开“用量与容量”，点击标题可手动收起；同一次任务的轮询更新不会重置展开状态，新任务重新默认展开。节点提问、大纲/正文、课件/讲义、多图总结及单独的结构/数学复核均使用相同的统计组件。

面板区分当前请求和整个任务累计：输入、缓存命中输入、缓存未命中输入、输出、思考用量（平台提供时），以及回答正文接收量、导图JSON体积和独立附件体积。导图体积复用已有草稿字符串，不为秒表重复序列化整图；它表示最近一次排队保存的快照体积。累计按随机调用编号去重，不把轮询快照重复相加；思考token作为输出的明细，不再次计入总输出。缺失字段保持未知，部分请求未提供用量时累计注明“部分”。平台只提供输入总数和缓存命中数时，可计算差值并明确标注。

官方DeepSeek和Kimi端点请求附带 `stream_options.include_usage=true`；自定义代理和其余接口保持原有请求参数，解析其实际返回的usage。不会为获取统计重复调用模型。依据：[DeepSeek流式协议](https://api-docs.deepseek.com/api/create-chat-completion/)、[输入缓存字段](https://api-docs.deepseek.com/guides/kv_cache/)、[Kimi官方开发者支持说明](https://forum.moonshot.ai/t/api-not-fully-openai-compatible/67/2)。
