# 提问的完整依据与角色共享

节点提问理解阶段沿用关联与定向员、回答员两个角色，不增加知识正确性审查员；生成后的受限分节排版复核见 [节点内分节复核](node-section-review.md)。两者现在接收相同的当前节点、对话、实际图片/PDF页和完整原始提炼，关联员另外获得可选资料列表；回答员再获得关联员的选取结果与说明。图片以实际多模态输入发送给两者，不把图片编码当作普通文字。

## 从首次理解保留材料

- 当前节点、关联节点、已选历史消息不再按8000、2400、1800等字符数裁短。历史按完整消息选取；全文超出应用容量时明确拒绝，不悄悄截断公式、选项或末尾结论。节点/消息数量的相关性筛选仍保留。
- 原图、原PDF优先于旧导图摘要和旧回答。早期完整提炼标为original-extraction并保留全文，供对照原件，不宣称是独立核验后的事实。
- 提示词要求先完整理解题干、全部选项、条件和承接步骤，再组织短回答。100～250字是展示目标，必要完整解题可适度超出；不能借此删除理解依据或必要论证。
- 既有讲义新流程仍是全文索引→完整语义单元→回读原页，compact及分组保留正文全文；不恢复旧版每节点180字符的融合输入。
- 关联员与回答员都须核对完整题面；本轮未提供原件、摘要省略、原件实际看不清是不同状态，不可未经核实归因于OCR截断或原件缺页。

## 原件来源与追问

ai-source-context.js通过明确的节点/提问记录关系查找原件，不用标题相似度猜附件。现有aiTurnId、generatedIds、parentTurnId及sourceId支持旧导图追问找到最初图片节点。新记录另保存sourceMaterials，原图片节点移除后仍可使用尚存文件；不保存图像编码。

PDF生成节点通过outlineSourceId与citations定位原文档和页码。嵌入附件从导图读取；未嵌入但仍保存在后台任务的原件从任务读取。页面同号的不同文档分别标注，不混淆题目和答案。用户明确指定页码时覆盖继承范围；题号不作为页码。关联早期extract的完整正文，避免把旧merge裁剪残片当作唯一依据。尚未保存的原件、已清理任务原件或文件读取失败会明确报告，不调用模型猜测所谓OCR缺口。

“仅当前节点”的范围排除无关节点，但仍保留该节点可追溯的原始依据。每次提问都会准备这些原件，无须等用户说“重新识别”才带图。学习背景和已有短链、单连接、撤销、学习进度逻辑继续使用。

## 运行与验证

更新后重启本地服务并强制刷新页面。首次理解和追问两位角色都接收视觉输入，理解阶段的角色数量不变，视觉输入量会增加；生成后分节复核按上述独立说明计费与记录。本次没有把提问任务迁移到后台持久队列，也不会自动改写现有旧答案。

`node tools/verify-question-sources.cjs`验证来源回溯、旧图、完整正文、同图共享、编码排除、容量超限和融合不截断；`node tools/verify-question-sources-ui.cjs`用独立Edge及临时图片/PDF验证实际表单发送、旧文字节点重读原图、PDF多来源同页码、原件失败和保存记录。测试使用本地假模型，验证程序交给模型的依据是否完整一致，不将其视为真实模型OCR和语义正确性的保证；实际使用中若仍有理解问题，再评估审查员。
