# 队长交接必提醒：服务器部署另行处理

当前交付是**单用户、本机Node服务的讲义后台任务**，没有部署远程后台。浏览器关闭后，只要本机服务、电脑与网络仍在，任务继续；本地服务重启后保留阶段记录，需要手动继续。

交接时请明确提醒队长：不能仅修改监听地址或去掉localhost来源校验后直接公开运行。下面是上线前需要另行落实的工程任务。

## 账号、权限与模型配置

- [ ] 将任务、原PDF、导图、结果、学习背景和模型配置关联到登录用户及课程；所有状态查询、下载、停止、恢复、领取、清理都检查权限。当前本地任务编号与localhost来源检查不构成多用户鉴权。
- [ ] 与课程系统的登录会话、CSRF策略、允许来源、跨域/反向代理路径统一。嵌入iframe时单独验证认证与任务恢复流程。
- [ ] 决定使用平台模型凭据还是用户自己的凭据；密钥服务端加密保存、隔离访问，不回传给浏览器、不进入任务或日志。限定可访问的模型地址及网络出口，处理服务器请求任意地址的风险。

## 队列、持久化与恢复

- [ ] 将本地文件队列和单进程持有锁替换为数据库事务、任务租约和可恢复队列；支持多实例/多worker，避免同时处理同一任务和重复计费。
- [ ] 部署独立后台worker及进程守护，明确重启、发布、优雅停止、任务迁移和备份恢复策略；不要随API实例重启丢失任务身份。
- [ ] 任务幂等、阶段检查点与模型调用账本落到共享持久存储。上游已受理但本地未收到结果时，不承诺“精确一次”；按服务商能力处理幂等键、用量核对及需要用户确认的重试。
- [ ] 将上传原件、阶段资料和结果放到持久卷或对象存储；容器临时盘不可作为唯一资料库。设置断点上传、完整性校验、生命周期/自动过期与备份。

## 配额、原生运行环境与成本

- [ ] 安装兼容Node.js、原生Canvas及对应CPU/系统的二进制依赖；使用锁文件安装，并在目标Linux/容器上验证文字、扫描件、公式、中文字体和PDF图层。
- [ ] 按用户配置上传大小、页数、存储、并发、模型token与费用上限；限速并公平调度，防止单个用户占满worker或模型额度。
- [ ] 为PDF解析设置CPU、内存、时间和进程隔离，处理异常/损坏/恶意PDF及原生解码器崩溃；选择有界重试策略，不自动反复发送付费请求。
- [ ] 配置HTTPS、上传/请求限制、代理超时和可观测性；进度连接只是展示，断开不取消任务。日志排除模型密钥、原件编码及不必要的个人学习内容。

## 结果与用户体验

- [ ] 远程任务状态、最终结果和领取标记跨设备一致；补充用户离线期间的完成/失败提醒与任务历史分页。
- [ ] 用导图修订号及原子应用操作处理多个设备同时编辑/领取；不能只靠当前本地的短期领取互斥和客户端记录防止冲突。
- [ ] 对照课程附件是否已经上传服务器，避免重复传输；“不嵌入导图”仍需后台可读原件，须明确保留期限和删除语义。
- [ ] 验收切换标签页、关闭浏览器、客户端断网/关机、API重启、worker崩溃、多实例竞争、取消与结果重复领取，核对费用与阶段调用次数。
